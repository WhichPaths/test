# LLM 基座决策模型：生产方案（目标：全面超过 Laya）

日期 2026-09-27 · 资源 64×H200 · 目标 4 周出可上线候选

---

## 0. 结论

1. **范式**：以 Qwen3.5 LLM 为基座，去掉 LM head 和解码循环，在决策位置接类型化判别头（Choice / Score / Noul），用严格 proper scoring rule 训练，再在留出数据上校准。一次前向给出全部选项的概率。这是 Jev 官方描述的方向（"预训练 LLM + RLCD"，细节未公开）。Kev、Decider、AutoJev 这些公开复现都是"Qwen 基座 + 决策读出"，已经验证可行。
2. **为什么能赢 Laya**：Laya 没有用 LLM，用的是 421M 的 ModernBERT 编码器。它强在小和快，弱在知识、长文和数据量：
   - 零样本在 typed-decisions 上只有 0.362，低于"每题都选多数类"的 0.461；
   - Decision Index 只有 16.4；
   - 超过 20 个选项就崩（Banking77 只有 0.425）。

   这些正是 LLM 基座和大规模训练数据能补上的。
3. **产品分档**，全部以 LLM 为基座：
   - **主模型**：默认 Qwen3.5-9B，精度档，同时当教师。第 1–2 周用同样的数据和预算，与 Qwen3.8-27B（稠密）、Qwen3.6-35B-A3B（MoE）做尺寸对比，按"记分卡 × 推理成本"定终选（§2.1、§7.4）。只超过 Laya，9B 足够；若还要追平 Jev 的知识类题目，大概率需要 27B 级。
   - **快速档 Qwen3.5-2B 或 0.8B**：从主模型蒸馏，服务低时延、低成本场景，第 3 周按实测精度和时延二选一。
4. **训练目标**：以软交叉熵（即 log score）为主，Score 题加 RPS。两者本身就是严格 proper scoring rule，直接求导优化即可。RL 只用于只有执行结果、没有完整标签的数据。
5. **算力富余**：9B 一轮主训练在 64 卡上约 2 小时量级（估算，见 §8）。瓶颈在数据和评测，不在算力，多出的算力用于多臂对照和多种子。
6. **与上一版停训方案的关系**：沿用"全文联合读取、9B 全参、MS-SWIFT、准入流程"。去掉研究假设，新增对 Laya 的记分卡、数据引擎、蒸馏分档和排期。

## 1. 对手：Laya 怎么做的（已核对其源码和公开报告）

### 1.1 模型

| 检查点 | 编码器 | 参数 | 上下文 | 选项预算 | 用途 |
|---|---|---|---|---|---|
| `laya` | ModernBERT-large | 421M | 512 | 192 token | 英文 |
| `laya-multilingual` | mmBERT-base | 322M | 1,024（可到 8,192） | 256 token | 100+ 语言 |
| `laya-typed-decisions` | ModernBERT-large | 421M | 1,024 | 256 token | 在 typed-decisions 训练集上微调 |

- **结构**：编码器全参微调，加一个从头训练的决策头（2 层 Transformer、选项标记打分器、act/escalate 头）。状态和**一个**问题拼成一条序列，每个选项在自己的 `[MASK]` 位置打分，再在该题的选项间做 softmax。同一状态的多个问题会重复编码状态。
- **路由**：按文字脚本/语言在 0.5 ms 内选英文或多语言检查点。原因是英文检查点在非拉丁文字上会高置信地全错：高棉语准确率 0.000，置信度 0.952。

### 1.2 训练（来自其微调 notebook）

- **损失**：软交叉熵（权重 1.0）加一个策略梯度项。策略梯度项的做法：
  - 对 logit 加零均值高斯噪声，σ 从 0.4 降到 0.1，每组 4 个样本；
  - 以 log + spherical + RPS 这些 proper score 作奖励，组内均值作基线。

  Laya 称之为 RLCD。目标分布已知时，这一项只是同一个 proper score 的高方差估计，主要作用来自软交叉熵。
- **typed-decisions 微调**：1,200 个训练案例（6,000 个决策），4 个 epoch。编码器 LR 2.5e-5、头 1e-4，有效 batch 64，max_len 1024，两张 T4 即可完成。
- **校准**：留出 10%（最多 400 条），按题型拟合温度。
- **基础检查点的训练数据**：未完整公开，只注明 AG News、BoolQ 在训练集中。

### 1.4 它自己承认的弱点（都是我们的机会）

1. **零样本不可用**：能力全部来自在目标数据上微调。
2. **选项多了就崩**：所有选项挤在固定的 192/256 token 预算里，77 个选项每个只剩 3–4 token。
3. **`noul` 跟着标签字面走**："true/false"两个标签会压过状态内容（issue #156）。
4. **否定不可靠**：取消类的否定请求，英文检查点 4/4 选错（#377）。
5. **位置偏置**：多语言检查点在 Score 题上几乎不选第一个等级（#131）。
6. **act/escalate 头没有信号**：AUROC 只有 0.30，能用的只有置信度（AUROC 0.77）。
7. **长文不稳**：超过约 4,000 token 后准确率不稳定。
8. **软分布匹配差**：软准确率 0.471，Jev 是 0.580。
9. **出厂过度自信**：多语言检查点没有拟合温度。

注意：typed-decisions 的标签本身来自 LLM 教师，教师自一致只有 0.735。Laya 的 0.766 和 verdict 的 0.771 都已超过这个上限，再往上主要是在拟合标注者的习惯。这个基准要赢，但不作为主要优化目标。

## 2. Jev 范式：照做什么、澄清什么

**照做：**
- 预训练 LLM 底座，提供知识、长文和复杂 JSON 的理解；
- 去掉 LM head 和自回归解码，一次前向出结果；
- 输出只能是调用方给定的选项，不存在格式错误；
- 概率必须经得起可靠性曲线的检验，才能拿来当自动化的阈值。

**四点澄清**（避免在错误方向上花算力）：

1. **ECE 不能当训练目标。** ECE 是分桶后的整体统计量：一个永远输出基准率的模型 ECE 为 0，却毫无用处。训练要用严格 proper scoring rule，即 log score（=交叉熵）、Brier，有序题用 RPS；ECE 只用来评估。Laya 的实现用的也是 log + spherical + RPS 奖励，不是 ECE。
2. **有标签时不需要 RL。** 目标分布已知时，proper score 可以直接求导最小化；对 logit 加噪声做策略梯度，只是同一目标的高方差估计。
   - Laya 的损失里软交叉熵权重是 1.0，RL 项是叠加上去的；
   - 你们自己的三组复验也没测到 RLCD 的稳定收益；
   - RL 的用武之地是只有执行结果、没有完整标签的数据，例如工具调用成功与否（§5.3）。
3. **"没有温度参数"不成立。** Laya、Kev、AutoJev、Decider 都在留出数据上拟合温度。
   - Kev 的教训：在同分布开发集上拟合的温度，迁移不到难的、远分布的数据；改在留出数据集上拟合后，ECE 从 0.059 降到 0.0085。
   - 校准是在某个数据分布上测出来的性质，换领域要复测，必要时重新拟合。
4. **交叉熵本身不会造成过度自信。** 在决策头上，交叉熵就是 log score，是 proper 的。LLM 概率失真主要来自 RLHF，以及在大词表上读取文字概率。决策模型的过度自信来自过拟合、标签噪声和分布漂移，用软标签、早停和温度校准解决。

### 2.1 Jev 会不会就是"Qwen 27B 稠密 + SFT + RL"？

有可能，但无法确认。TypeSafe 只公开了两点：
- 从预训练 LLM 出发、不经过 RLHF，直接做 RLCD（TypeSafe 的路线图：LLM → RLCD，与 RLHF → RLVR 并列）；
- "新架构、并行采样器、一次前向"。

没有论文，没有公开基座、损失函数和训练细节。

**支持"27B 级 Qwen + SFT（+RL）"的证据：**
1. **Qwen 27B 稠密 + 纯 SFT 已经到了 Jev 的水平。** AutoJev-27B 基于 Qwen3.8-27B，全参 SFT 7.3 万条、286 步、单卡 H200，在 Decision Index 0.2 上得 50.94，Jev 是 51.67。
2. **27B 的容量装得下 Jev 的决策。** 社区的 JEV-27B / JEV-9B 是把 Jev 的完整输出分布蒸馏到 Qwen3.8-27B / Qwen3.5-9B 上。27B 版只训了约 1.09 亿参数（LoRA + 决策头），单卡 B200 约 9 小时。它们是学生模型，不是官方 Jev。
3. **知识水平像 27B 级以上。** Kev-9B 在决策格式下 MMLU 0.74，Jev 是 0.90，差距主要在知识类题目。

**不太支持"稠密 27B"的证据：**
4. **价格。** Jev 输入每百万 token 0.042 美元。27B 稠密每百万 token 的前向约 5.4e16 FLOPs，按 H100 约 2 美元/小时、40% MFU 算，成本约 0.07 美元，高于售价。按这个价格赚钱，更像是 MoE（例如 35B-A3B 这类每 token 只激活约 30 亿参数）或更小的稠密模型；也可能是补贴定价。
5. **时延。** 第三方测到 API 的 p50 为 236–276 ms，其中含网络开销，区分不了模型尺寸。

**对我们的含义：**
- 不需要知道 Jev 的确切做法。公开复现已经说明，"Qwen 基座 + 决策头 + proper scoring 的 SFT + 留出集温度"就能到 Jev 的水平。
- RL 最多是增量：你们的三组 RLCD 复验没有稳定收益，Laya 的 RLCD 实际是软交叉熵加带噪策略梯度。
- 因此流程定为：先 SFT（§5.1）→ 可选的短 RL 阶段（§5.3）。RL 必须在留出集的 NLL/ECE/准确率上胜过纯 SFT 检查点才保留。
- 基座尺寸用实验定（§7.4）：9B、27B 稠密、35B-A3B MoE 同预算对比。

## 4. 模型设计

### 4.1 输入格式（与 `POST /v1/systemone` 请求同构）

```
<|state|>{状态：文本 / 邮件 / 工单 / 日志 / JSON}
<|question|>{type} | {instructions}
<|opt|>{key_1}: {description_1}<|opt_end|>
<|opt|>{key_2}: {description_2}<|opt_end|>
...
<|decide|>
```

- 新增特殊 token，embedding 可训练。
- **Score**：每个等级作为一个选项，按量表顺序排列。
- **Noul**：渲染成"成立：{陈述}"和"不成立：{陈述}"两个选项，输出 P(成立)。
- **Choice**：训练时随机决定键的呈现方式（语义键、A/B 字母、不显示键），迫使模型读描述和状态，而不是读标签字面。这一条专门针对 Laya 的 #156。
- 训练时随机打乱选项顺序；Score 等级保持量表顺序，因为顺序本身有语义。

### 4.2 读出头（替代 LM head）

- **去掉 LM head**：你们 v5 已经这样做，文本参数 79.4 亿。
- **指针头**：把 `<|decide|>` 位置的隐状态 h_d 和每个选项 `<|opt_end|>` 位置的隐状态 h_i 组合，送进一个两层 MLP：

  s_i = w·GELU(W[h_d; h_i; h_d⊙h_i] + b)

  再在该题的选项间做 softmax。
  - h_d 上加题型嵌入；三种题型共享同一个头，参数约 1–3 千万。
  - 因果注意力下，只有 `<|decide|>` 能看到全部选项，所以由它负责比较。
- **输出**：Choice 给分布和首选；Score 给等级分布，量表是数值时再给期望；Noul 给 P(成立)。
- **弃答头**：一个小 MLP，输入 h_d 和 logit 统计量（最大值、间隔、熵），输出"首选正确"的概率。它只在**留出数据**上训练，因为在训练数据上模型过度自信，学不到有用信号。Laya 的 act 头 AUROC 0.30 就是反例。
- **对照臂**（第 2 周消融）：标签槽读出，即 Decider 的做法——只保留 A–Z 等标签 token 那几行 LM head，在答案槽读 logit。

### 4.3 同一状态的多个问题

- **v1**：每个问题一条序列，状态重复编码。和 Laya 相同，实现最简单，先上线。
- **v2**：状态作为共享前缀只算一次，每个问题作为从状态末尾分叉出去的分支，分支之间互不可见。
  - Qwen3.5 是 Gated DeltaNet 和全注意力的混合结构，分叉时要同时复制注意力 KV 和线性注意力的递推状态，不能只靠注意力掩码。
  - Kev 在 Qwen3.5 上用了共享前缀加分支的做法。
  - typed-decisions 每个案例 5 个问题，v2 在多问题请求上直接省下重复编码状态的计算。

### 4.4 对 Laya 已知失败点的逐项对策

| Laya 失败点 | 我们的做法 | 验证 |
|---|---|---|
| 零样本不可用 | LLM 基座 + 几百万条跨领域决策训练 | typed-decisions 零样本、留出任务 |
| 超过 20 个选项崩 | 不设固定选项预算；训练覆盖 2–255 个选项；更多候选时先召回 | Banking77、高基数套件 |
| noul 跟标签字面走 | 标签用词随机化；陈述式渲染；成立/不成立对照对 | 换标签用词套件 |
| 否定出错 | 否定/肯定对照对增强，由执行器或教师复核 | 否定对照 500 对 |
| 位置偏置 | 换序增强；两种顺序之间加对称 KL（openJev-verdict 用这招把翻转从 7.41% 降到 4.76%） | 换序翻转率 |
| 非拉丁文字高置信全错 | 多语言基座 + 50 种以上语言的训练数据 + 按语系校准 | MASSIVE 51 种语言逐语言 ECE |
| 长文不稳 | 分阶段加长到 32K；把关键证据埋进长文档训练 | 1K/4K/8K/32K 埋证据套件 |
| act 头无信号 | 弃答头只在留出数据上训练 | AUROC、风险—覆盖曲线 |
| 软分布匹配差 | 软标签训练，保留多标注者/多模型分布 | 软准确率、Brier |

### 4.5 分档

| 档 | 基座 | 部署 | 定位 |
|---|---|---|---|
| L | Qwen3.5-9B（默认；按 §7.4 可换 27B 或 35B-A3B） | H200 / L40S | 主模型、教师、难请求 |
| S | Qwen3.5-2B 或 0.8B（第 3 周定） | L4 / A10 级 GPU | 高并发、低时延 |
| M（可选） | Qwen3.5-4B | 同 L | 成本折中 |

三档共用输入格式、读出头和 API；S 档的低置信请求自动升级到 L 档。

## 5. 训练目标

### 5.1 主损失

对每个问题 q，t_q 是目标分布，p_q 是模型分布：

```
L = Σ_q [ CE(t_q, p_q)
        + 0.5 · RPS(t_q, p_q) · 1[q 是 Score]
        + 0.2 · symKL(p_q, p_q^换序) ]
```

- **t_q 的来源**：金标签（one-hot）、多标注者分布、大模型集成分布、执行器给出的确定答案。
- **Brier 项**（系数 0 或 0.5）作为消融。Kev 测过"CE + Brier"不胜过单独 CE，所以不默认开。
- 不用 ECE 做损失（§2）。

### 5.2 蒸馏到 S 档

```
L_S = KL(p_主^(T=2) ‖ p_S^(T=2)) + 0.5 · CE(t_金, p_S) + 0.5 · RPS + 0.2 · symKL
```

主模型的软分布保留了"几个选项都有可能"的信息，这正是 Laya 最弱的软分布匹配。

### 5.3 可选的第 3 阶段：结果反馈（上线后）

生产日志里有"判定 → 执行 → 结果"的记录，比如路由后是否被转回、工具调用是否成功。这类数据只有执行结果、没有完整标签：
- 用 proper score 做奖励，按选中动作的实际结果训练 P(成功)；
- 需要探索时，用组内基线的策略梯度。

这是 RL 真正有用的地方，第一版不依赖它。

### 5.4 校准

- **温度**：按（题型 × 选项数区间 × 领域/语系）拟合，拟合数据来自训练中完全没出现过的数据集，并做折外检查。温度写入模型配置。
- **在服务精度下拟合**：Laya 实测 bf16 相对 fp32 会让概率最多偏移 0.073，所以温度和阈值要在上线用的精度下拟合和验证。
- **阈值**：产品侧按"能接受的错误率"从风险—覆盖曲线上选；模型不承诺某个阈值普遍安全。

## 6. 数据

### 6.1 来源与规模

| 类别 | 来源 | 规模（决策数） | 标签 |
|---|---|---:|---|
| A. 已有 typed 语料 | 你们规范化的多源记录（typed hard/soft、规则、workflow、NLI、ToolACE、Agent），完成全局准入后使用 | ~200 万 | 原有硬/软标签；规则类由执行器给 |
| B. 公开决策数据 | 只用训练切分，且许可允许商用：意图（CLINC150、HWU64、MASSIVE 训练切分…）、主题、情感、毒性、事实核查、有序评分、工具选择（Toucan、ToolACE、NVIDIA Agent） | 100–150 万 | 原标签；多标注者的保留分布 |
| C. 合成工作流状态 | 50 个以上业务场景（客服、发票、安全事件、Agent 轨迹、合同、HR、IT、物流、风控…）× 三种题型；状态形式有工单、邮件、日志、JSON、表格 | 100 万个状态 × 约 5 题 ≈ 500 万 | 大模型集成软标签；规则类由执行器给 |
| D. 阅读/知识 | 从 4,302 万 DQA 中抽取，转成单选；用 step1000 挖同话题难负例，去掉语义等价答案 | ≤ 150 万 | 原答案 |
| E. 多语言 | 从 A–C 抽样翻译成 50 种以上语言，以 MASSIVE 的 51 种为主 | 200–300 万 | 继承源标签，抽检翻译质量 |
| F. 鲁棒性增强 | 在 A–E 上生成：否定对照对、标签换词、换序、加干扰选项、把关键证据埋进 4K–32K 长文档 | 约占总量 15% | 执行器或教师复核 |
| G. 高基数 | 意图全集、分类树、工具目录，20–255 个选项 | ~50 万 | 原标签 |

- **主模型训练集**：以上去重后约 300–500 万个决策。先做 10 万 → 50 万 → 200 万的规模曲线，找到拐点再定总量和轮次；不为凑量重复采样。
- **蒸馏集**：主模型对 1,000–2,000 万个决策输出软分布（A–G 全部，外加额外的合成状态），S 档在这上面训练。
- **step1000 的用途**：只当 D 类的难负例挖掘器和大候选集的召回器，不当初始化（它在决策任务上与基座无显著差别，Score 还退步了）。

### 6.2 合成状态的标注

1. **大模型集成**：用开源、许可允许商用的大模型集成，例如 Qwen3.5-397B-A17B、DeepSeek-V4 系列、Qwen3.6-35B-A3B（逐一核对许可）。
   - 先对全部样本做单次前向，直接读各选项的概率；
   - 熵高或模型间分歧大的样本，再用推理多次采样，取经验分布；
   - 模型间系统性冲突的样本标为"有歧义"，只作软标签或丢弃。
2. **执行器**：规则、政策、权限、预算类状态由程序给出确定答案；证据不足时标"无法确定"，不硬猜。
3. **禁止项**：不用 Jev 的输出当训练标签（服务条款风险）；闭源模型最多用来抽检评测标签。

### 6.3 清洗、去污染、许可

- **准入**：沿用你们现有流程（父组、角色闭包、来源账本）。
- **去污染**：对所有评测集做精确匹配 + 13-gram + 向量近重复去污染。评测集包括 typed-decisions 测试集、Laya 的留出任务、MASSIVE/XNLI 测试切分、Banking77、JevBench、Decision Index，以及你们的 2,000 题和 19,174 final。
- **许可**：
  - XNLI、ANLI 是 CC BY-NC（非商用），只进评测，不进生产训练。你们语料里待准入的 ANLI 14.9 万条要排除。
  - MASSIVE 是 CC BY 4.0，可用，但需署名。
  - 仅限研究用途的数据同样只做评测。
  - 每个来源的许可记入账本。
- **质量抽检**：每个来源抽 300–500 条，人工或强模型复核。错误率超过 10% 的来源降权或剔除。

## 7. 训练配方

### 7.1 主模型（以 9B 为例）

| 项 | 设置 |
|---|---|
| 框架 | MS-SWIFT（HF 后端）+ DeepSpeed；自定义模型、collator、loss |
| 分片 | 先实测 ZeRO-1 与 ZeRO-2：<br>• 9B 的 BF16 权重加梯度约 36GB，FP32 主权重和 Adam 状态分片后每卡只有几 GB，ZeRO-1 放得下，而且梯度只在累积边界同步一次；<br>• DeepSpeed 的 ZeRO-2 实现在每个 micro-step 都做规约 |
| 单步 token | 每卡每个 micro-step 打包 8K–16K token。上一轮每卡只有 16 对短 QA，通信远大于计算 |
| 学习率 | 主干 1e-5，读出头 1e-4；预热 2%，余弦降到 10% |
| 精度 | BF16 计算；FP32 主权重和 Adam；梯度通信用 BF16 |
| 长度 | 主阶段 ≤ 8K；长上下文阶段 32K，占 token 5–10%，保留短任务回放 |
| 轮次 | 主阶段 1–2 epoch，按规模曲线定 |
| 初始化 | 原始后训练的 Qwen3.5-9B |
| 资源 | 主训练 32 卡；消融每臂 16 卡 |

**消融**：每臂约 2 亿 token、16 卡，都在第 2 周完成。对比项：
1. 指针头 vs 标签槽读出；
2. 有无合成数据 C；
3. 有无 DQA 阅读数据 D；
4. 软标签 vs 硬标签；
5. Brier 项开关；
6. 换序 KL 开关。

### 7.2 S 档（蒸馏）

| 项 | 2B | 0.8B |
|---|---|---|
| 损失 | §5.2 | §5.2 |
| 学习率 | 2e-5 | 3e-5（头 1e-4） |
| 数据 | 蒸馏集 2 epoch | 同左 |
| 长度课程 | 1K → 4K → 8K | 同左 |
| 资源 | 16–32 卡 | 16 卡 |

两个尺寸都训，第 3 周按"记分卡 × 同卡时延"选定。

### 7.3 领域微调轨道

在 typed-decisions 的 1,200 个训练案例上微调，和 laya-typed-decisions 正面比较。这个结果单独列一行，不混进零样本成绩。

### 7.4 主模型尺寸对比（第 1–2 周）

同一份数据（约 50 万决策、约 4 亿 token）、同一套头和损失、同样的评测：

| 臂 | 基座 | 训练方式 | 资源 | 推理成本（相对 9B） |
|---|---|---|---|---|
| A | Qwen3.5-9B | 全参 | 16 卡 | 1× |
| B | Qwen3.8-27B（稠密，AutoJev 同款基座） | 全参（ZeRO-3/FSDP）或 LoRA | 32 卡 | 约 3× |
| C | Qwen3.6-35B-A3B（MoE，你们已有训练经验） | 全参，路由器低学习率并锚定原路由 | 16–32 卡 | 约 0.3–0.5×（按激活参数估算） |

**选择规则：**
- 以记分卡为主，尤其是 Decision Index 知识区、Banking77 和留出任务；
- 同时考虑单位请求成本和 p50/p95 时延；
- 27B 只比 9B 高 1–2 分时，默认选 9B 或 MoE；
- 选出的主模型同时当蒸馏教师。

27B 全参 30 亿 token 约需 4.9e20 FLOPs，64 卡约 6 小时（按 35% MFU 估算），算力不构成限制。

| 任务 | 计算量 | 耗时 |
|---|---|---|
| 9B 主训练（30 亿 token） | 6 × 9B × 3e9 ≈ 1.6e20 FLOPs | 64 卡约 2 小时 / 32 卡约 4 小时 |

## 9. 评测

- **框架**：第一天建好统一的 `/v1/systemone` 请求格式。同一批输入同时跑 Laya 三个检查点、我们的模型和零样本 9B，参照组加 Kev-9B、Decider-4B。结果全部落盘，可以复算。
- **套件**：
  1. typed-decisions：零样本和微调两种口径；
  2. Laya 的共享基准（17,416 题）：用其仓库的基准脚本生成完全相同的题目，覆盖 MASSIVE 51 种语言、XNLI 15 种语言、AG News、BoolQ、DAIR Emotion、prompt-injections、SST-5、Banking77；
  3. JevBench 公开部分，以及同版本的 Decision Index；
  4. 你们的 2,000 题和 19,174 final；
  5. 鲁棒性套件：
     - 否定对照 500 对；
     - noul 换标签用词：300 题 × 3 种用词；
     - 换序翻转；
     - 长文档埋证据：500 题 × {1K, 4K, 8K, 32K}；
     - 高基数：20–255 个选项。
- **统计**：配对自助法置信区间；最终候选跑三种子。
- **时延**：准备一台 T4（或 L4），加一台 CPU 机器，Laya 和我们的快速档在同一台机器上测单题、同状态 5/10 题和批量吞吐；9B 在 H200 上测。

## 10. 服务

- **接口**：TypeSafe 兼容的 `POST /v1/systemone`。返回每个选项的概率、首选、置信度、弃答标记、模型版本和耗时。
- **引擎**：
  - vLLM 自定义 pooling 模型，只取标记位置的隐状态。Decider 的 vLLM 路径在 B300 上中位 32 ms，与原生实现 argmax 一致率 99.6%。
  - 或自研推理服务：HF + CUDA graphs + 按长度分桶批处理。
- **前缀缓存要实测**：vLLM 对 Qwen3.5 混合模型的前缀缓存按较大的块对齐（Qwen3.5-4B 上是 528 token），比块短的 prompt 一次都命中不了（有报告 Qwen3.5-4B 的 QPS 因此从 200 掉到 100 以下）。同状态多问题的共享（§4.3 v2）放在自己的服务里实现，不依赖自动前缀缓存。
- **精度**：主模型在 H200 上用 FP8，上线前与 BF16 做一致性检查（max|Δp| ≤ 0.03，argmax 一致 ≥ 99.5%），并在 FP8 下重新拟合温度。
- **分流**：S 档低置信的请求升级到 L 档；L 档低置信的请求转人工或交给生成式大模型。
- **运维**：影子流量 → 灰度；监控置信度分布漂移、弃答率和时延；每次发版必跑固定回归集。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 教师错误被学生放大 | 金标签 CE 项做锚；大模型集成；每个来源抽检；主模型在留出集上的成绩作为 S 档上限参考 |
| typed-decisions 标签噪声（上限 0.735） | 只作为门槛之一，不针对它调参 |
| 主模型时延和成本高于 Laya | 主模型定位服务端精度档；需要低时延、低成本的场景用 S 档 |
| 快速档在同卡上单题慢于 Laya | 共享状态编码追回多题请求；FP8/INT8 量化；必要时只上 0.8B |
| 混合架构的工程坑（分叉、前缀缓存、打包边界） | v1 先用每题一条序列上线；v2 分叉实现要做逐位对比测试；打包时核对递推状态在样本边界清零 |
| 许可 | 账本记每个来源的许可；NC 数据只做评测；不用 Jev 输出训练 |
| 合成数据风格单一 | 50 个以上场景、多种状态形式、多模型打标；按场景留出一部分做评测 |
