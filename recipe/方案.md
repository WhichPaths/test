## 1. 两个判断，决定整套方案

### 判断一：你的库存和你的短板是反的

把 94 库里 agent 数据按子域拆开：

| agent 子域 | 条数 | 占比 | 模型在对应能力上的位置 |
|---|---:|---:|---|
| SWE 仓库修复 | 2,307,058 | **48.1%** | SWE-bench 73.4，**最强项** |
| tool_use 工具调用 | 1,299,874 | 27.1% | MCPMark 37.0，**最弱项** |
| 未细分 | 521,185 | 10.9% | — |
| terminal 终端 | 374,154 | 7.8% | Terminal-Bench 51.5，强 |
| interactive 多轮 | 278,880 | 5.8% | TAU3 待测，疑似弱 |
| web_app + search + office | 14,878 | **0.3%** | 几乎没有数据 |

一半的 agent 库存砸在模型已经最强、而且开源教师普遍弱于它的 SWE 上；最弱的 MCP / 工具调用只有 27%，搜索和办公加起来 0.3%。**按库存配比，就是把算力花在最不需要的地方。**

### 判断二：8 天的瓶颈不是算力，是数据

你上一轮实测 2.87B token / 约 3.25 小时 / 64 卡 = **0.88 B token/小时**。

一次设计得当的 SFT，本方案算下来 19.85B 曝光 token ≈ **25 小时**。8 天 192 小时 ≈ 可以跑 7.7 次这样的训练。

所以算力是富余的，真正的约束是：开源数据里"教师强过 Qwen3.6"的部分很薄，硬拿 token 填满 8 天只会过训练、掉通用。

**结论：8 天买的不是"一次更长的训练"，而是"多个候选 + 评测门 + 权重合并"。** 这恰好是"agent 涨、通用不掉"这个约束最直接的解法——它本质是个多目标取舍问题，靠多臂比较和合并解，不靠训得更久解。

## 2. 配比方法（可复算的公式，不是拍脑袋的比例）

### 第一步：给每个域打瓶颈类型

这是和"只用强 model"那版最大的区别。"教师必须强于学生"这条规则太粗，会把 Toucan 这类数据错杀。正确的切法是看**瓶颈在哪**：

| 瓶颈类型 | 什么在卡 | 教师政策 | 覆盖哪些域 | 占比 |
|---|---|---|---|---|
| **推理** | 解法质量 | 教师必须强于 Qwen3.6，否则往下拉 | SWE、强教师工具轨迹 | 6.6% |
| **覆盖** | 见没见过这种工具 / 环境 / 轮次结构 | 环境和任务多样性 > 教师 IQ；教师略弱也能用，前提是执行验证通过 + 重渲染成原生格式 | MCP、多轮、搜索、终端、技能 | 35.5% |
| **风格** | 输出习惯、约束遵循 | 教师 IQ 基本不影响；要的是和 base 风格一致 | 中文、IF、安全、多语 | 35.3% |
| **保持** | 只求不退 | 只做 retention，1 遍，不追提升 | 数学、代码、知识 | 22.6% |

所以 **Toucan 的教师是 Qwen3-32B / Kimi-K2 / GPT-OSS-120B，都弱于 Qwen3.6，但它照样该用**——因为 MCPMark 37.0 卡的是"没见过这 495 个 server 的 schema"，不是"推不出来"。反过来，**CoderForge / Nemotron-SWE-v1,v2 / SWE-Hero 这些 Qwen3-Coder-480B（SWE≈69.6）产的轨迹要拉黑**，因为 SWE 卡的是解法质量，73.4 的学生学 69.6 的老师是往下走。

### 第二步：算 agent 侧权重

对每个 agent 子域 d：

```
gap_d     = max(0, (ref_d − base_d) / ref_d)        ref = 同级开源模型该基准最好成绩
usable_d  = 1.0  若有瓶颈匹配、可验证的数据；否则 0.3
w_d       ∝ gap_d × usable_d ，再 clip 到 [3%, 25%] 后重新归一
```

### 第三步：通用侧设地板，不按库存分

```
通用监督 token 占比 ≥ 40%（retention floor，不可让）
通用内部按"当前能力值 × 回退代价"分，不按库存量分
```

40% 这个地板有依据：SPT 论文的混合消融里，30% 技能数据 + 通用数据得 agent 38.60，纯技能训练只有 22.06，纯通用 15.56——**混合显著优于纯 agent 训练**，通用数据不只是保底，它本身就抬 agent 分。近期持续训练工作也把 replay 比例从旧的 5–20% 上调到 25–50%。

### 第四步：三条硬约束

- 单一源数据集 ≤ 全局 15%（防单源过拟合）
- 单一 agent 子域 ≤ agent 预算 25%（多样性约束）
- 同任务最多保留 2 条有实质区别的路径

多样性这条不是保守，是有实验支撑的：DIVE 报告**多样性扩展在数据量少 4 倍时仍优于数量扩展**；OpenThoughts-Agent 做了 100+ 组消融，结论是"任务多样性卡住 SFT 的 scaling"，他们只用 10 万条就在 7 个 agent 基准上做到 44.8 平均分，超过 Nemotron-Terminal-32B 的 40.9。

### 第五步：小规模验证权重，再上大跑

这就是 RegMix / data mixing laws 的思路降本用法：不训几百个代理模型，而是在 S1 用 4 个短臂（2 组配比 × 2 个学习率）实测，选出真正的最优配比再上主训练。

## 6. 八天怎么排

| 阶段 | 时长 | 资源 | 产出 |
|---|---:|---|---|
| S0 冻结与校准 | 14 h | 推理 + 64 卡 2 h | 数据冻结、真实模板 token 统计、吞吐实测、base 全量基线 |
| S1 四臂探索 | 40 h | 2 作业 × 32 卡 | 4 个候选：配比 ×2 × 学习率 ×2，各约 5B token |
| S2 选臂 | 8 h | 推理 | 定下配比 + 学习率 |
| S3 主训练 | 44 h | 64 卡 | 19.85B 曝光；20/40/60/80% 四道评测门 |
| S4 退火 + 合并 | 20 h | 64 卡 + 1 节点 | 退火 2.5B；WiSE-FT α 扫描 |
| S5 终评与导出 | 34 h | 推理 | 全量评测、去污染核查、导出 |
| 余量 | 32 h | | 重跑一臂 / 128K 长上下文阶段 |

合计 192 h。S3 给了 44 h 而计划只需 25 h，是留给吞吐不及预期的（长轨迹占比高，实测可能掉到 0.7 B/h）。

**四道评测门是用来提前停的，不是用来看的。** 任一通用关键域出现可靠下降（配对差 95% 置信区间上界 < 0）就停止追加，回到上一道门的 checkpoint。

如果你坚持要把 8 天的 token 填满：把唯一数据扩到约 250 万条 / 20B 唯一 token，2 遍 = 40B 曝光 ≈ 50 h。但我不建议——多出来的量只能从教师更弱的池子里补，边际收益递减而遗忘风险上升。多跑两个臂更划算。

## 7. 训练配置

| 项 | 设置 | 依据 |
|---|---|---|
| 起点 | 原始 Qwen3.6-35B-A3B | 和上一轮 step-686 完全独立 |
| 打包 / 批次 | 64K packing，GBS 64 个 packed 序列 | 3:1 线性注意力配比，40 层里只有 10 层全注意力，长序列比普通 Transformer 便宜得多，64K 可行 |
| 学习率 | WSD：warmup 1% → 恒定 → 最后 12% 衰减到峰值 5% | 恒定段每个 checkpoint 都能直接用；cosine 中途停下来学习率没降完，价值打折 |
| 峰值 LR | 5e-6 与 1e-5 在 S1 对照 | |
| router LR | 主 LR 的 1/10 | 防止微调早期路由被打乱 |
| **软路由锚定（RPB）** | router logits 往冻结 base router 的先验拉，router 本身仍可训；**不要重新施加均匀化 load-balancing loss** | Router Prior Bias 在 Moonlight-16B-A3B 数学后训上：RPB 45.77 / 重施 LBL 31.91 / 无锚定 29.44，且 OOD 保持更好；已在 Qwen3-30B-A3B-Base 复现。base 路由里已有的专家协同结构会被均匀化目标抹平 |
| **KL 锚定到冻结 base** | 只在通用 retention 那部分 batch 上开 | Palmyra x6 的 ASFT：token 加权 + KL anchor，在通用不退的前提下拿到 BFCL Core 0.785。冻结副本只有 3B 激活，全开约 +30% 算力，半开约 +15% |
| loss mask | 工具返回 / 环境观察 / 历史 user 全部 loss=0；只监督 reasoning + tool_call + final answer | 环境注入的 token 模型没选过，算进 loss 会污染梯度 |
| 双模式 | think / no_think 都要覆盖，比例对齐 base 的使用分布 | 只训一个模式，另一个会退化 |
| 视觉塔 | LR × 0.1 或冻结 | 见风险 1 |
| 退火数据 | 最后 12% 只用验证等级最高的切片：SkillGym、Orchard、V4-Pro / Claude Opus 4.8 轨迹、中文 / IF / 安全 / 多模态 | 最好的数据放最后 |
| 存盘 | 每 6 h，保留 2 份；HF 快照只在 5 个评测点 | |

### 合并（几乎免费，但效果最直接）

```
θ(α) = (1 − α)·θ_base + α·θ_sft ,  α ∈ {0.5, 0.6, 0.7, 0.8, 0.9, 1.0}
```

对每个 α 跑 agent 和通用两套评测，画 Pareto 前沿取拐点。这一步只要合并 + 推理，不占训练算力，但通常能在几乎不掉 agent 分的前提下把通用退化拉回大半。**"agent 涨、通用不掉"这个约束，合并比调配比更好使。**

## 9. 风险清单

1. **视觉会塌。** 模型是 VLM，94 库**全是纯文本**。20B token 的纯文本 SFT 几乎必然损伤图像 / 视频能力，而且这条上一版方案完全没提。三选一：补 G8 的 2.5 万条图文数据、冻结视觉塔、或靠合并拉回。至少 MMMU / MathVista 要进评测。
2. **教师弱于学生。** 数学、代码、SWE 的主力开源教师是 R1 一代和 Qwen3-Coder-480B，公开成绩低于 Qwen3.6。这三个域只做 retention，1 遍，不追提升。
3. **库存与需求倒挂。** 见判断一。不按库存配比是本方案的前提。
4. **Toucan 教师偏弱但该用。** 它卡的是覆盖不是推理。前提是只取执行成功轨迹 + 重渲染成原生 tool 格式，混训多种框架格式本身就是工具调用出错的来源。
5. **已知的四个数据缺陷照旧要修**（上一版扫出来的，都是真问题）：OCR2 题目是占位符要按原始 dataset/split/index 恢复、OpenR1 的 correctness 必须绑定到具体那条 generation、Open-SWE 并行工具调用缺关联 ID 要隔离不能猜配、CoderForge 同任务重复要按任务指纹去重。
6. **存储。** 上一轮 4 份 checkpoint 占 2.1T，共享盘只剩约 608G。续训状态（`iter_*`）可删、HF 权重（每份 67G）留着评测，能腾出约 1.9T。**开训前必须先清。**
7. **均长全是假设。** 表里 18 个域的输入 / 监督均长都没实测，token 预算会随实测显著变化。S0 第一件事就是用真实模板重算。

---

## 10. 落地顺序

1. 先清存储（腾 1.9T），否则后面都跑不动。
2. 跑 base 全量基线评测——包括视觉和长上下文。**这一步决定 gap_d，没有它第 2 节的公式算不出来。**
3. 下载第 5 节的 7 个新数据集，核 SHA-256 和行数；同时给 G8 / G9 选型。
4. 按 `source_quota.csv` 做全量筛选：恢复缺题 → 按源解释正确性字段 → 合并任务族 → 跨源去重 → 评测去污染 → 统一渲染成 Qwen3.6 原生格式 → 真实 token 化。
5. 用实测 token 数重跑 `build_mixture.py`，冻结 manifest。
6. 按第 6 节排期开训。
